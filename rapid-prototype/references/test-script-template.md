# Test script template

Use this structure for `test-script.md`. Replace the bracketed guidance.

```markdown
# Test script — [prototype name]

## What we're finding out

**Question:** [the brief's question, verbatim]
**Linked experiment card:** [name, if any] — right if [threshold]; stop if [threshold]
**Format:** [moderated in person / moderated remote / unmoderated link] · [N] sessions · [length] minutes each

## Who we need

[One-sentence description of the participants.]

### Screener

1. [Question that identifies the audience] — *include if:* [answer]
2. [Question on recent relevant experience] — *include if:* [answer]
3. [Question that screens out unrepresentative people, e.g. "Do you work in [sector]?"] — *exclude if:* yes
4. [Question to get a spread — e.g. age band, area, digital confidence]
5. "Which of these can you use for a 45-minute session?" [options]

**Mix we're aiming for:** [e.g. at least half who've never used a similar service; at least two over 60]
**Thank-you payment:** [amount and form — pay people for their time]

## Before the session

- [ ] Prototype open on the test device, facilitator panel checked (`?` key or `#facilitator`), then closed
- [ ] Reset the prototype
- [ ] Participant ID entered in the facilitator panel
- [ ] Note-taker ready with the observation grid

## Introduction and consent (read aloud, ~3 minutes)

"Thanks for coming. We're testing an early idea for [one-line description], and we'd like to see how it works for you.

We're testing the idea, not you. There are no wrong answers, and if something's confusing, that's exactly what we need to know. I didn't design it, so you won't hurt my feelings.

This is a mock-up. Nothing you type is saved or sent anywhere, and no real booking or payment happens.

As you go, please think out loud — say what you're looking at, what you expect, and what you're unsure about.

[We'd like to record the screen and audio so we don't have to take notes the whole time. Only the project team will see it, and we'll delete it by [date].] Is that OK?

You can stop at any time, and skip anything you'd rather not do. Any questions before we start?"

## Warm-up (~5 minutes)

- [Question about their current situation related to the problem]
- [Question about the last time they faced it — what did they do?]
- [Question about what they've tried before]

## Tasks

For each task, read the scenario, hand over the device, and stay quiet unless they're stuck for more than a minute.

### Task 1 — [short name]

> "[Scenario in everyday language — the situation and goal, not the steps]"

**Done when:** [the screen or state that counts as complete]
**Watch for:** [the specific moments the brief's question depends on — e.g. reaction at the price screen]
**After the task:** "How did that go?" · "Was there anything you expected that wasn't there?"

[Repeat for Tasks 2–3.]

### If they go quiet or get stuck

- "What are you thinking right now?"
- "What did you expect to happen when you did that?"
- "What would you do now if I weren't here?"
- After a minute stuck: "Where would you look for that?" — and if still stuck, note it and move them on.

**Don't:** point at things, name buttons, explain the design, or ask "would you use this?" mid-task.

## Debrief (~5 minutes)

- "In your own words, what is this for?"
- [Question tied to the brief's question — e.g. "What did you think of the delivery charge?"]
- "What would stop you using something like this?"
- "Is there anything you'd change first?"
- Only at the very end, and treat as weak evidence: "If this existed near you, how likely would you be to try it?"

Download the log from the facilitator panel and thank them.

## Observation grid (one per participant)

| Task | Completed? (yes / with help / no) | Time | Hesitated at | Said | Log reference |
|---|---|---|---|---|---|
| 1 | | | | | |
| 2 | | | | | |

## Synthesis (after all sessions)

1. **Completion table** — tasks × participants
2. **Drop-off points** — where people stopped or needed help, from the grids and logs
3. **Issues** — group observations; rank by how many participants hit each, and how badly (blocker / slowed down / minor)
4. **Answer the question** — one paragraph answering the brief's question directly, with the numbers
5. **What this can't tell us** — e.g. rates in the wider population, long-term use
6. **Hand back** — if there's an experiment card, complete its learning card
```
